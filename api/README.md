# Document Export API client

The producer-owned OpenAPI source is
[`../contracts/openapi.json`](../contracts/openapi.json). The Document Export
Service repository is authoritative; consumers must not reconstruct the
contract from controller source or depend on runtime `/v3/api-docs` output.

The Java client is generated by `client/pom.xml`. Its immutable version is
derived from the contract semantic version and the first 12 characters of the
reviewed source revision:

`3.0.0-rev.2d6edd832027`

Generated source remains below `client/target/` and must not be committed.
Publication runs only from `develop`, refuses to overwrite an existing
coordinate, and proves that a fresh authenticated Maven consumer can resolve
and compile the package.

The 2.0.0 contract deliberately makes the approved Gateway service identity
and owner context mandatory. It is therefore a major-version boundary from the
initial unauthenticated 1.0.0 contract.

The additive 2.1.0 release publishes the optional replacement-workflow
idempotency header. It does not make the header mandatory for existing
consumers.

The 3.0.0 release makes the ordinary-export `Idempotency-Key` mandatory. This
is an intentional major-version boundary that lets durable generation resume
DOCX/PDF Store writes safely after a lost response.

For subsequent releases:

1. Change service behavior and `contracts/openapi.json` together.
2. Increment `info.version` according to semantic compatibility.
3. Update `contracts/SHA256SUMS`.
4. Record the merged contract revision and digest in `client-release.json`.
5. Set `initialRelease` to `false` and record the prior published contract
   revision as `compatibilityBaseRevision`.
6. Update the client and smoke POM versions together.
7. Merge the producer change before publishing or updating a consumer.

The compatibility gate rejects removed paths, operations, responses and
properties, required-parameter narrowing, newly required properties, changed
operation IDs and enum-value removal.
