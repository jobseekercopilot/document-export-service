# Edited document replacement

The replacement endpoint accepts an application-linked CV or cover letter in
DOCX format and creates a new immutable document version. It does not overwrite
the selected version.

## User-visible behaviour

1. The service verifies that `documentKind` matches the stored document.
2. It imports readable text from DOCX headers, body paragraphs, tables and
   footers into the new version's canonical content.
3. It creates that version as inactive and records its source as `UPLOADED`.
4. It stores the original edited DOCX and renders a PDF from the imported text.
5. It activates the new application/document-kind version only after both
   files have been stored.
6. The response returns the new document ID and its current DOCX/PDF files.

If import, conversion or either storage operation fails, the previous version
remains active. An incomplete new version can remain inactive for diagnosis and
safe retry; it is never presented as the application's current version.

## Supported edit semantics

- DOCX is the only accepted upload format for private beta.
- `PDF` remains in the published `uploadedFormat` client enum for compatibility
  with the 2.0 contract, but the endpoint returns `400` for that value.
- Text in headers, paragraphs, table cells and footers is imported.
- List paragraphs retain bullet meaning in the canonical text.
- The standard `Generated with Job Seeker Copilot` footer is removed before
  rendering so it is not duplicated.
- The original DOCX remains available as the authoritative uploaded file.
- PDF styling is regenerated by Job Seeker Copilot. Arbitrary Word layout,
  fonts, images, shapes, tracked changes and other advanced formatting are not
  promised to round-trip.
- The document must already have an application link. Canonical application
  linking is owned by DOCGEN-16.

The Document Store performs its own DOCX safety and archive validation before
accepting the uploaded bytes. Wider malware/content inspection and resource
budgets remain separate beta work under EXPORT-02.

## Safe retries

Clients should send a stable `Idempotency-Key` of 1–128 URL-safe characters and
reuse it only when retrying the same replacement. Document Export derives
separate stable keys for document creation, DOCX storage and PDF storage.
Document Store will replay matching completed steps and reject a changed
request that reuses a key.

Retries without an `Idempotency-Key` are treated as new replacement operations.
